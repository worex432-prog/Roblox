# OpenGLOverlay — графический оверлей и набор игровых модулей

## Frame sync и Nametags

Сборка с дополнительными функциями создаётся скриптом `build_features.bat`; DLL
появляется в `build_features/mob.dll`.

В настройках Triggerbot → Blatant переключатель **Frame sync** включён по
умолчанию. В этом режиме атака выполняется на игровом потоке по текущему
`hitResult`, без очереди `SendInput`. Сохраняются проверка готовности удара,
правила падения, исключение друзей, выбранная цель и случайный интервал.
Режим не имитирует удержание кнопки. Если **Frame sync** выключен, используется
`SendInput` с удержанием 100–110 мс; этот способ не обнаруживает цель, которая
попала под прицел и вышла из него между обновлениями `hitResult`.

**Nametags** — отдельный модуль. Нажмите ПКМ на его карточке, чтобы открыть
настройки, включая **Range** (1–256 блоков). Подписи отображаются поверх стен,
друзья отмечаются зелёным. Дальность, переключатели и назначенная клавиша
сохраняются в конфигурации. Модуль показывает только игроков, уже загруженных
клиентом: увеличение дальности не загружает дополнительные чанки. При расчёте
позиции учитываются камера, FOV и интерполяция игроков; наклон камеры и
покачивание от ходьбы могут немного смещать подписи.

Новые функции используют именованные JNI-методы Minecraft, как и остальная
часть backend. Успешная сборка сама по себе не подтверждает совместимость
маппингов с конкретной версией игры. Проверьте Frame sync и положение Nametags
непосредственно в игре. Если DLL уже загружена, перезапустите игру перед
установкой новой версии.

Оверлей построен на Dear ImGui и MinHook; для перехвата кадров используется
`wglSwapBuffers`. Ассеты перенесены из архива, интерфейс собран по макетам:
тёмная и светлая темы, разделы Main, Options и Cleaner, карточки модулей,
переключатели, слайдеры, настройки модулей, привязки клавиш и список друзей.

Шрифт, картинка и семь иконок **встроены в DLL** (RCDATA), рядом с DLL никаких
файлов не нужно. Макеты `assets/*.png` — это референсы дизайна, в рантайме они
не используются; фоны `assets/backgrounds` нужны только превью, чтобы рендеры
совпадали с макетами.

## Сборка

```powershell
cmake -S . -B build
cmake --build build --config Release
```

Результат:

* `build/Release/test_overlay.dll` — сам оверлей;
* `build/Release/injector.exe` — инжектор.

Готовые бинарники также скопированы в `outputs/` (`test_overlay.dll`,
`injector.exe`).

Зависимости (Dear ImGui 1.91.6, MinHook 1.3.4) подтягиваются через
`FetchContent`; если исходники уже лежат в `build/_deps`, сеть не нужна.

## Использование

Рекомендуемый способ — `injector.exe`: запустите его **один раз** (нужны права
администратора). Он остаётся в трее, сам качает `payload.dll` с GitHub в память
(без файла на диске), находит новые окна Minecraft и внедряется в них. После
закрытия игры следующий запуск подхватывается автоматически. В трее доступны
счётчик внедрений, лог `injector.log` и «Выход».

Старый ручной вариант (для `test_overlay.dll`):

```powershell
# по имени процесса
injector.exe game.exe C:\path\to\test_overlay.dll
# или по PID
injector.exe 1234 C:\path\to\test_overlay.dll
```

* `Right Shift` — показать/скрыть меню (Insert тоже работает). Клавиша
  опрашивается каждый кадр через `GetAsyncKeyState`, а не через `WM_KEYUP`:
  игры с raw input не всегда доставляют отпускание клавиши в оконную процедуру,
  из-за чего хоткей раньше «не срабатывал».
* Иконки сверху: солнце/луна — тема, шестерёнка — Options, домик — Main,
  ластик — Cleaner, крестик — закрыть меню.
* **ЛКМ по карточке** (по самой карточке или по тумблеру) — включить/выключить
  функцию; вокруг тумблера пробегает короткое кольцо-подтверждение.
* **Клавиша модуля** (показана в правом нижнем углу карточки) — то же самое:
  Toggle-модули переключаются по нажатию, Hold-модули активны, пока клавиша
  зажата. Бинд меняется кликом по этой клавише.
* **ПКМ по карточке** — раскрыть/свернуть панель модуля; «минус» в правом
  верхнем углу панели тоже сворачивает её. Панель раскрывается под карточкой и
  сдвигает карточки ниже; в одной колонке открыта максимум одна панель, поэтому
  всё влезает в меню.
* Модули Main и их подфункции (набор перенесён из старого клиента `mob_v21`):
  * **Triggerbot** — способ бинда (`Бинд`: Hold / Press / LMB hold), режим
    (`Режим`: Legit / Blatant), тип критов (`Криты`: Комбо / Умные криты),
    `Дистанция атаки` (1–5 блоков, по умолчанию 3.5), `Delay min`, `Delay max`.
    Задержка и удержание всегда случайные (в обоих режимах). Триггер ищет цель под прицелом
    сам, а не только в ванильном радиусе 3 блока: на 3 блоках удар проходит как
    обычный, а на 4–5 блоках триггер всё равно замахивается по цели, но урон
    засчитывает только сервер и только если цель в его собственной дистанции.
    По умолчанию триггер включён, забинжен на **Z** с активацией **Press** и
    режимом **Legit**.
    Физические клики не блокируются ни хуком оконных сообщений, ни фильтром
    raw input, ни маской `GetAsyncKeyState`: ЛКМ в инвентаре, настройках, чате,
    при ломании блоков и еде работает как обычно. Подфункция **«Бинд»**:
    * **Hold** — триггер активен, пока зажата клавиша модуля;
    * **Press** — клавиша переключает триггер (как старый Default);
    * **LMB hold** — клавиша переключает модуль, а бить триггер начинает только
      после того, как физическая ЛКМ была зажата 40–60 мс. Первый удар остаётся ручным: физический
      клик проходит в игру, а через 40–60 мс триггер отпускает кнопку и дальше
      бьёт своими кликами.
    Подфункция **«Режим»**:
    * **Legit** — удар наносится инжектированным кликом бэкенда (прежний
      Default), ЛКМ не участвует, если не выбран бинд LMB hold;
    * **Blatant** — удар наносится через JNI `Minecraft.startAttack()` на игровом
      потоке (порт из tb1). Как и в tb1, байткод `Minecraft.tick()` переопределяется
      через JVMTI: удар и клик выполняются внутри тика игры, а не из хука
      swap-буфера. После удара отправляется настоящий SendInput-клик ЛКМ на
      35–55 мс (слышно и прокликивается), но в тик-хуке обнуляются
      `keyAttack.isDown` и `clickCount`, поэтому второй атаки не происходит.
      Если SDL игнорирует SendInput, остаётся визуальный флаг
      `MouseHandler.isLeftPressed`. Если JVMTI недоступен, используется запасной
      путь через swap-буфер. Важно: DLL теперь экспортирует точки входа JVMTI
      (`Agent_OnAttach`), поэтому для хука тика её нужно грузить через
      `inject.py` из репозитория payload — он сам вызывает `jcmd JVMTI.agent_load`
      после LoadLibrary. Как только цель появляется под прицелом, Blatant
      сбрасывает старую задержку и бьёт с реакцией 0–5 мс; последующие удары по
      этой цели идут со случайной задержкой 50–75 мс.
    Триггер не бьёт, когда игрок ест/пьёт, держит щит или использует любой
    предмет (`isUsingItem` / `isBlocking`).
    Подфункция **«Криты»**: **Комбо** бьёт сразу после зарядки меча, **Умные
    криты** ждут окна крита. Старые «тупые криты» полностью убраны, их значение
    в конфиге мигрирует в умные.
    Клик триггера в Legit — короткое нажатие 40–60 мс, как обычный клик мышью.
    Ванильный кулдаун промаха (`missTime`, ~500 мс) сбрасывается на каждом
    проходе бэкенда — и при ручных ударах, и при триггере. Сам заряд меча не
    ускоряется. В бинде LMB hold после перехвата этот кулдаун используется,
    чтобы физический клик не бил; там он сбрасывается прямо перед кликом
    триггера.

    Клик не считается зажатым, поэтому после резкого разворота оверлей не бьёт
    сам по воздуху; удар с быстрым отводом камеры от хитбокса не «залипает» —
    следующий клик проходит сразу, как только меч зарядился.

    Подфункция **«Ломание при
    триггере»**: когда прицел наведён на блок, триггер не кликает и не забирает
    удержание — зажатая ЛКМ продолжает ломать блок как в ванилле, пока прицел
    остаётся на блоке. Работает для ЛКМ-бина;
  * **Aim Assist** — по умолчанию забинжен на **X (Toggle)** и подфункция **«Только при
    движении мыши»**: модуль остаётся включённым постоянно, но не двигает
    прицел, пока физическая мышь стоит на месте, и начинает работать с первым
    движением. Собственные инжектированные движения оверлея не считаются
    движением мыши (фильтр `LLMHF_INJECTED` и `hDevice == NULL` в raw input),
    поэтому аим не может «раскачать» сам себя. Вторая подфункция — **«Аим только
    после удара»**: каждый удар (ручной или от триггера) открывает окно 1–10 с
    (слайдер `Сброс аима`), в течение которого аим помогает; когда окно
    заканчивается, прицел не трогается до следующего удара. Окно открывается
    сразу по свингу по существу под прицелом, поэтому оно работает и тогда,
    когда камера уводится сразу после удара (подтверждение урона с задержкой
    сервера для этого больше не требуется). FOV действует и внутри этого окна:
    существо, по которому был нанесён удар, учитывается только пока оно в
    пределах настроенного FOV — стоя спиной к цели аим её не трогает. Внутри
    FOV у последнего удара небольшой приоритет, чтобы быстрый разворот обратно
    доводил прицел именно на эту цель, а не на соседнюю.
    Далее **Legit**: `Рандом
    скорости`, `FOV`, `Range`, `Сглаживание` и либо `X min`/`X max`/`Y min`/`Y max`,
    либо `Скорость X`/`Скорость Y`; **Blatant**: `Randomize`, `Только X`, `FOV`,
    `Range`, `Сглаживание`, `Random`, `Скорость X`, `Скорость Y`.
    Третий режим **`test`** не имеет подфункций — только ползунок `Скорость`
    (1–10). Он читает чувствительность мыши из настроек Minecraft, переводит
    градусы в mouse-counts по реальной формуле Minecraft 26.3
    `(s*0.6+0.2)^3*8*0.15`, сглаживает движение по времени кадра (а не по
    пикселям), наводится только по горизонтали преимущественно в центр
    хитбокса (иногда чуть ближе к краю) и вообще не трогает ось Y. Пока ты
    двигаешь мышь физически, аим ничего не инжектит и не мешает тебе; как только
    прицел оказался на хитбоксе — аим тоже полностью отключается. Если ты сам
    свалил с хитбокса и мышь стоит, он мягко возвращает прицел обратно
    (скорость задаётся ползунком). Подфункции режима `test`: `Сенса (0=авто)`
    — впиши чувствительность из настроек Майна в процентах (100% = 1.0; 0 — читать из игры), `Скорость`,
    `Только при движении мыши` (когда рука стоит — аим молчит) и `Держать цель`
    (0–10 с — не переключаться на другую цель);
  * **Auto Clicker** — CPS, Разброс CPS, Задержка старта;
  * **Click Pearl** — `Задержка`;
  * **Crystal Spam** — `CPS`;
  * **AutoSwap** — по умолчанию включён и забинжен на `C`; подфункции `Бинд` и
    `Скорость` (1–20, по умолчанию 20).
    Макрос открывает инвентарь, сразу нажимает клавишу левой руки (F) над тем
    слотом, на котором уже стоит курсор (при открытии инвентаря это слот ниже
    левой руки), и сразу закрывает инвентарь (E → F → E). Из хотбара ничего не
    берётся: свопается именно слот под курсором. Курсор не трогается вообще —
    он не двигается, не телепортируется и не подсвечивает слоты. Если игра ещё
    не сопоставила курсор со слотом (или он стоит на пару пикселей мимо), слот
    под курсором определяется по геометрии окна и свопается тем же вызовом,
    который делает игра при нажатии F (`handleContainerInput(..., 40, SWAP,
    ...)`). Клавиши инвентаря и левой руки читаются из настроек Minecraft,
    поэтому переназначенные E/F работают сразу;
  * **HeadSwap** — по умолчанию выключен, бинд `B`; подфункции `Бинд`, `Слот` (1–9) и
    `Скорость` (1–20). Открывает инвентарь, плавно ведёт курсор к слоту шлема и
    нажимает клавишу выбранного слота хотбара (например `R`), затем закрывает
    инвентарь. Движение курсора сделано как настоящее движение мыши: 48–240
    точек с шагом ~2 мс, плавное ускорение и торможение (smoothstep), мягкие
    дуги и одна и та же мелкая дрожь руки на весь проход, поэтому траектория
    не дёргается и не повторяется между запусками. Весь путь занимает около
    480 мс на скорости 1 и около 200 мс на скорости 20; после него курсор
    коротко отдыхает на слоте, чтобы нажатие клавиши было точным;
  * **Friend Add** — друзья (см. ниже).
* **Friend Add** — друзья: бинд (по умолчанию `F`) добавляет игрока, на которого
  вы смотрите, в список; рядом живут радиус поиска (1–32 блока) и ручное
  добавление ника. Aim Assist и Triggerbot обязаны пропускать ники из списка —
  для этого в `gui.cpp` есть `ui::IsFriend(name)`, которую вызывает выбор цели.
* Options: тема, масштаб интерфейса, прозрачность панелей, скорость анимаций,
  счётчик FPS, сброс настроек (сброс — в два клика: «Сбросить» → «Точно сбросить?»).
* Cleaner → выбрать «Unhook» или «Unhook + cleaner» → **нажать на картинку с
  аниме**: она и есть кнопка выгрузки. Оба режима снимают хук, возвращают
  оконную процедуру и **выгружают DLL из процесса игры** (через
  `FreeLibraryAndExitThread`); «Unhook + cleaner» перед выгрузкой ещё вызывает
  клинер. Пункты взаимоисключающие, как радио-кнопки.

## Превью без инжекта

```powershell
cmake -S . -B build-preview -DOVERLAY_BUILD_PREVIEW=ON
cmake --build build-preview --config Release --target preview

# интерактивное окно (клики, перетаскивание слайдеров, темы, вкладки)
preview.exe
preview.exe --size 1600x900 --light

# офскрин-рендер в BMP
preview.exe --out shot.bmp --size 1920x1080                 # Main, тёмная
preview.exe --out shot.bmp --size 1920x1080 --light         # Main, светлая
preview.exe --out shot.bmp --size 1920x1080 --open 0        # с панелью модуля
preview.exe --out shot.bmp --size 1920x1080 --open 1 --mode 1  # Aim Assist, Blatant
preview.exe --out shot.bmp --size 1920x1080 --page 1        # Options
preview.exe --out shot.bmp --size 1920x1080 --page 2        # Cleaner
preview.exe --out shot.bmp --size 1920x1080 --bg path\to\bg.png  # свой фон
```

Без `--out` (или с `--live`) открывается обычное окно: тот же код интерфейса,
но на рабочем столе — можно покликать вкладки, раскрыть карточку, потянуть
слайдеры, переключить тему. Окно можно растягивать, интерфейс масштабируется.
Закрыть — крестиком в интерфейсе или крестиком окна.

Превью рисует тот же код (`ui/gui.cpp`), но в FBO, и сохраняет кадр в BMP —
удобно сравнивать с макетами. Фон подставляется из `assets/backgrounds`:
тёмная тема — `dark.png`, светлая — `light.png`, при переключении темы картинки
плавно перетекают друг в друга. `preview/shots/` содержит готовые рендеры всех
восьми состояний в 1920×1080.

## Клинер

Настоящего клинера пока нет, поэтому `cleaner.cpp` — заглушка: `RunCleaner()`
вызывается ровно в тот момент, когда нужно (хуки уже сняты, DLL ещё в
процессе), и пишет строку в `%LOCALAPPDATA%\OpenGLOverlay\cleaner.log`, чтобы
шаг был проверяем. Когда появится настоящий клинер, достаточно заменить тело
`RunCleaner()` — порядок «снять хук → почистить → выгрузиться» уже вшит в
`dllmain.cpp`.

## Настройки и конфиг

Всё, что меняется в интерфейсе, сохраняется автоматически (через ~0.4 с после
последнего изменения) и подгружается при старте — и в игре, и в превью:

```
%LOCALAPPDATA%\OpenGLOverlay\config.ini
```

Если запись туда недоступна (например, ограниченные права или песочница),
файл кладётся рядом с модулем: `config.ini` возле DLL / `preview.exe`.
Путь показывается внизу страницы Options.

Хранится: тема, масштаб, прозрачность, скорость анимаций, FPS, друзья (ники и
радиус) и по каждому из шести модулей — включён ли, режим (Legit/Blatant), три
слайдера, клавиша и Toggle/Hold. Формат — простой INI, его можно править руками:

```ini
[ui]
light=1
scale=1.2000
fps=1

[m0]
enabled=1
mode=0
key=571
v00=12.000
v01=0.000
v02=0.000

[friends]
count=2
radius=8.000
name0=Steve
name1=Alex

[aim]
fov=12.00
range=6.00
smooth=55.0
random_strength=2.00
speed_x=220.0
speed_y=165.0
x_min=70.0
x_max=100.0
y_min=150.0
y_max=220.0
speed_rand=0
randomize=1
x_only=0
move_only=0
after_hit=0
after_hit_seconds=3.00
lock_after_hit=0
lock_seconds=3.00

[trigger]
delay_min=50
delay_max=75
range=3.500
break_after_hit=0
block_manual_lmb=0
block_manual_lmb_key=0
click_hold_min=40
click_hold_max=60

[crystal]
cps=10.00

[pearl]
delay=40
```

Каждый модуль хранит по три значения на каждый режим: `v00`…`v02` — режим
Legit, `v10`…`v12` — Blatant (второй набор использует только Aim Assist).
Старые конфиги читаются тоже: `v0`/`v1`/`v2` и `smooth`/`speed_x`/`speed_y`
подхватываются как значения режима Legit.

`Сброс настроек` возвращает дефолты и сразу пишет их в файл. Офскрин-рендер
превью (`--out`) конфиг не читает и не пишет, чтобы скриншоты были
детерминированными.

## Про иконки

В архиве иконки лежат по две: чёрная и белая (32×32, PNG с альфой). В проект
встроены белые версии, а цвет задаётся тинтом из палитры (`ImDrawList::AddImage`),
поэтому в тёмной теме они белые, в светлой — тёмные, без второй копии в
ресурсах. Все карточки модулей используют один значок — `icons/swords.png`
(скрещённые мечи из набора). Галочка в чекбоксах векторная: в наборе её нет.
На каждую PNG-иконку есть векторный fallback на случай, если текстуру не
удалось создать.

## Анимации

Всё сглаживается по времени и не зависит от FPS (`Approach` в `ui/gui.cpp`):

* переключение темы — цвета интерфейса и фон `dark.png`/`light.png` перетекают;
* карточка при наведении приподнимается и получает подсветку, тень растёт;
* включение функции — кольцо вокруг тумблера;
* появление/скрытие меню — fade + лёгкий «поп» (0.94 → 1.0 масштаба), при
  закрытии меню доигрывает обратную анимацию и не перехватывает ввод игры;
* ползунок «Скорость анимаций» в Options масштабирует скорость всех переходов;
* тумблер — плавный ход бегунка и перекраска дорожки;
* панель настроек раскрывается/сворачивается по высоте с обрезкой и fade-in;
* подчёркивание активной вкладки в навбаре скользит между иконками;
* иконки в навбаре увеличиваются при наведении; кнопка режима слегка «нажимается»;
* картинка-кнопка в Cleaner подсвечивается и чуть растёт при наведении.

## Как переносились пропорции

Макеты нарисованы на холсте 2174×1404, то есть 1087×702 в 1×. Интерфейс
верстается на фиксированной дизайн-сетке 1280×826,67 (тот же макет в других
единицах, с точно тем же соотношением 1087:702) и рисуется **ровно 1087×702
пикселя**, по центру окна — меню больше не растягивается на весь экран.
Уменьшается оно только если окно игры меньше этого размера. Ползунок «Масштаб
интерфейса» в Options домножает размер.

Под меню подложена картинка текущей темы: `assets/backgrounds/menu-dark.png` и
`menu-light.png` — ровно 1087×702, вырезанные по центру из `dark.png`/`light.png`
(обе 1920×1009) без растяжения пропорций и встроенные в DLL. Тёмная тема берёт
ночной кадр, светлая — дневной; при смене темы они плавно перетекают друг в
друга. Так как ассет и прямоугольник меню совпадают пиксель в пиксель, при
масштабе 1.0 фон рисуется 1:1, без повторной интерполяции.

## Про шрифт

`InclusiveSans-Regular.ttf` из архива содержит **только латиницу** — в нём нет
кириллицы (проверено по `cmap`). Русские подписи в шаблонных макетах набраны
другим начертанием, поэтому в `ui_font.cpp` кириллица подмешивается из
системного `segoeui.ttf` (fallback: Tahoma → Arial → Verdana) тем же размером:
латиница рисуется шрифтом шаблона, кириллица — системным, без «?» вместо букв.
Если в `assets` положить версию Inclusive Sans с кириллицей, fallback можно
убрать.

Дополнительно в `ui/gui.cpp` есть `kFontScale = 1.18f`: ImGui растрирует шрифт
так, что `ascent - descent` равно запрошенному размеру, а макеты измерялись
метриками FreeType (где размер — это em). Коэффициент переводит измеренные по
макетам размеры в номинальные размеры ImGui.

Атлас шрифта растеризуется в 32 px (`LoadUiFont(32.0f)`), а не в 64 px: меню
рисует почти все подписи в 15–25 px, и при атласе 64 px глифы приходилось
уменьшать втрое — буквы «рассыпались» и выглядели пиксельными. 32 px даёт
почти 1:1 для основного текста и остаётся чётким при штатном масштабе
интерфейса.
